# Level Model Documentation

-   **File:** `backend/app/Models/Lifecycle/Level.php`
-   **Purpose:** Represents a user level within a lifecycle stage, defining attributes like team limits, bonuses, and status.
-   **Key Attributes:**
    -   `name` (string)
    -   `url` (string, used as route key)
    -   `team_member_limit` (integer)
    -   `stage_id` (integer)
    -   `validate_years` (integer, for level expiry/renewal)
    -   `joining_bonus` (integer, percentage)
    -   `status` (boolean)
-   **Relationships:**
    -   `stage()`: `belongsTo` relationship to `Stage`.
    -   `users()`: `hasMany` relationship to `User`.
    -   `tasks()`: `hasMany` relationship to `LevelTask`.
-   **Traits:**
    -   `HasFactory`
    -   `HasRecordNavigator`: Custom trait for navigating records (e.g., `nextRecord()`).
    -   `HasSaleAccess`: Custom trait for sales-related access.
    -   `HasVoucherAccess`: Custom trait for voucher-related access.
-   **Implemented Features:** Defines user levels, their properties, and relationships to stages, users, and tasks. `getRouteKeyName()` uses `url` for route model binding.
-   **Usage:** Used to define the progression and benefits associated with different user levels in the platform's lifecycle system.
-   **Pros/Cons/Suggestions:**
    -   **Pros:** Clear structure for defining user levels and their associated rules.
    -   **Cons:** `joining_bonus` is an integer, implying a percentage, but this should be explicitly documented or handled with a custom cast/accessor to avoid ambiguity.
    -   **Suggestions:** Explicitly define the unit/meaning of `joining_bonus`. Document the functionalities provided by `HasRecordNavigator`, `HasSaleAccess`, and `HasVoucherAccess` traits.
